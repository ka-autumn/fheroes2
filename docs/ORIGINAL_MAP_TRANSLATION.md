# 原作形式マップの翻訳手順

MP2/MX2マップに埋め込まれた表示文言を洗い出し、日本語sidecarへ登録して検証する手順を示す。
マップ本体とセーブデータに保存される正本値は変更しない。

## 翻訳対象

1枚のマップには、次の文言が含まれる可能性がある。

* マップ名と説明文
* 指定日に表示される日次イベント本文
* 英雄が特定タイルへ進入したときに表示される地上イベント本文
* 看板と海上のボトルのメッセージ
* マップ作者が設定した城名と英雄名
* 酒場のカスタム噂
* スフィンクスの問いと答え

現在のsidecarは、名前、説明文、日次イベント、地上イベント、看板、ボトル、カスタム城名、
カスタム英雄名を扱う。カスタム噂または本文ありのスフィンクスが見つかった場合、監査ツールは
`unsupported`として報告する。正本を書き換えずに表示時解決できる設計を決めるまで、翻訳データを追加しない。

## 文言を洗い出す

リポジトリルートで次を実行する。座標は0始まりで表示される。

```sh
python3 script/tools/audit_original_map_translation.py build/maps/Alteris.mp2 --catalog-directory files/lang
```

ツールはMP2/MX2の情報ブロックをゲーム本体と同じ分類条件で読み、種類ごとに全件数、翻訳済み件数、
未翻訳件数、未対応件数を表示する。未翻訳または未対応があれば終了コード1、壊れたマップやTSVなら
終了コード2、全対象が翻訳済みなら終了コード0を返す。

日次イベントは、オブジェクトに関連付けられていない情報ブロックだけを対象とする。英雄などの
オブジェクト情報にも同じ位置に似た値が入ることがあるため、先頭バイトや本文オフセットだけで
分類すると空の日次イベントとして誤集計する。

## sidecarへ登録する

いずれのTSVもUTF-8、タブ区切りで、フィールド内にタブと改行を入れない。キーの原文は、空白と
句読点を含めてマップ内の値と完全一致させる。

### 名前と説明文

`files/lang/ja.map-translation.tsv`へ5列で追加する。

```text
ファイル名  原文名  原文説明  訳名  訳説明
```

キーは`ファイル名＋原文名＋原文説明`である。

### 日次イベントと地上イベント

`files/lang/ja.map-event-translation.tsv`へ5列で追加する。

```text
ファイル名  原文名  原文説明  原文イベント本文  訳文
```

両イベントは同じ形式を使い、キーは`ファイル名＋原文名＋原文説明＋原文イベント本文`である。

### 看板、ボトル、カスタム名

`files/lang/ja.map-object-translation.tsv`へ6列で追加する。

```text
ファイル名  原文名  原文説明  文言種別  原文  訳文
```

文言種別には`sign-message`、`bottle-message`、`castle-name`、`hero-name`のいずれかを指定する。
キーは`ファイル名＋原文名＋原文説明＋文言種別＋原文`である。同じ原文でも種類が異なれば別の訳を持てる。

## 検証する

1. 監査ツールを再実行し、対象カテゴリがすべて`untranslated=0`かつ`unsupported=0`になることを確認する。
2. `git diff --check`を実行し、TSVの列数、重複キー、空フィールドを監査ツールでも確認する。
3. CMakeでRelWithDebInfoをビルドする。ビルド後、3種類のsidecarが出力先の`files/lang`へコピーされていることを確認する。
4. 日本語UIでマップを開始し、対象文言を実際に表示する。
   * 日次イベントは発生日、対象プレイヤー色、繰り返し周期を確認する。
   * 地上イベントは報告された座標へ対象色の英雄を進入させ、報酬・損失も確認する。
   * 看板は英雄で調べ、ボトルは船で回収する。
   * 城名と英雄名は冒険マップ、城画面、英雄画面など複数の表示箇所で確認する。
5. 日本語で保存したゲームを英語UIで読み込み、正本の英語名と本文へ戻ることを確認する。

通常プレイで全件を発生させられない場合は、コミットしないデバッグ補助や検証用セーブを使用してよい。
完了記録には、通常プレイで確認した範囲、補助を使った範囲、確認できなかった範囲を分けて残す。
