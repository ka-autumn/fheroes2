# ADR-0001: 原作形式マップの表示用翻訳をsidecarで管理する

**Status:** Accepted

**Date:** 2026-09-13

**Deciders:** 開発者

## Context

MP2/MX2のマップ名と説明文はマップファイルに固定長で埋め込まれ、gettextを通らない。
正本値を書き換えると、セーブデータ、ハイスコア、スクリーンショット名、マップ選択状態などへ影響する。
ファイル名だけ、または原文だけの照合では、同名のユーザーマップへ訳を誤適用する可能性がある。

MP2/MX2の日次イベントと地上イベントの本文もマップファイルへ直接埋め込まれ、gettextを通らない。
イベント本文はセーブデータへ保存されるため、読み込み時に置換すると、そのセーブを別の表示言語へ
切り替えても訳文が残る。

## Decision

- `feature/cjk-support`を基点とする専用ブランチで、機構と初回の翻訳データを一体として実装する。レビューと差し戻しの単位を既存のCJK対応から分離できるためである。
- UTF-8のタブ区切りsidecarを`files/lang/<言語>.map-translation.tsv`へ置く。現行97枚の原文にはタブと改行がなく、差分の確認や行追加を簡単に保てるためである。
- `ファイル名＋原文名＋原文説明`の完全一致をキーとする。
- MP2/MX2の正本値は変更せず、シナリオ選択、ゲーム設定、ゲーム情報、セーブ情報の各画面で描画する直前だけ訳文を解決する。
- 現在のUI言語に対応する訳がない場合や複合キーが一致しない場合は原文を表示し、不一致をマップごとに一度ログへ残す。
- イベント本文は`files/lang/<言語>.map-event-translation.tsv`へ分離し、
  `ファイル名＋原文名＋原文説明＋原文イベント本文`の完全一致をキーとする。
- イベント本文の正本値は変更せず、日次イベントと地上イベントのダイアログを描画する直前だけ訳文を解決する。
- 現在のUI言語に対応するイベント訳がない場合や複合キーが一致しない場合は原文を表示し、
  不一致をイベントごとに一度ログへ残す。
- 看板、ボトル、カスタム城名、カスタム英雄名は`files/lang/<言語>.map-object-translation.tsv`へ分離し、
  `ファイル名＋原文名＋原文説明＋文言種別＋原文`の完全一致をキーとする。
- オブジェクト文言の正本値は変更せず、看板・ボトルのダイアログ描画時と、城名・英雄名の表示用参照時だけ訳文を解決する。
  セーブデータには引き続き原文が保存されるため、読み込み後に表示言語を切り替えられる。
- 酒場のカスタム噂は`files/lang/<言語>.map-rumor-translation.tsv`へ分離し、
  `ファイル名＋原文名＋原文説明＋原文の噂`の完全一致をキーとする。噂の正本値は変更せず、酒場のダイアログを描画する直前だけ訳文を解決する。
- スフィンクスの問いと答えは`files/lang/<言語>.map-sphinx-translation.tsv`へ分離し、
  `ファイル名＋原文名＋原文説明＋文言種別＋原文`をキーとする。問いは表示する直前だけ訳文を解決する。
  答えは正本を置き換えず、日本語UIのときだけ、正本の答えに対する追加の答えを正解として受け付ける。英語UIでは判定が従来と変わらない。
- 追加の答えは完全一致で判定する。正規化は、前後の空白の除去、全角・半角ASCIIの統一、英字の大文字小文字の無視までとし、
  ひらがなとカタカナは同一視しない。どの表記を正解とするかをsidecar上で読める形に保つためである。
- 従来の先頭4文字だけで判定する経路は正本の答えにだけ適用する。バイト単位の切り詰めが日本語の別名を誤って正解にすることを避けるためである。
- 現在の答え入力欄はASCII文字しか入力できない。追加の答えには当面ASCII表記を登録し、入力手段の拡張は別の作業とする。
- 追加・監査・実機確認の手順は[原作形式マップ翻訳の手順書](../ORIGINAL_MAP_TRANSLATION.md)にまとめる。

## Options Considered

### MP2/MX2を直接編集する

固定長制約、原本破損、他言語への切替不能、原作資産の再配布という問題があるため採用しない。

### 動的なgettext検索だけを使う

ユーザーマップの同一原文にも訳を適用し、通常の抽出処理もmsgidを発見できないため採用しない。

### ファイル内容のハッシュをキーにする

誤適用には強いが、販売版や軽微な改訂ごとに別ハッシュが必要になる。初版では可読な複合キーを採用し、必要になった時点で複数識別子を検討する。

### イベント本文を読み込み時に置換する

表示経路を一か所に集約できるが、置換後の本文がセーブデータへ保存され、表示言語を切り替えられなくなるため採用しない。

## Consequences

- 翻訳追加はsidecarの行追加だけで行え、マップ本体やC++コードを変更しない。
- 原文の句読点を含む完全一致なので、未知の版には安全側へ倒して訳を適用しない。
- sidecarは配布物へ含める必要があり、各プラットフォームの資産コピー設定を保守する。
- 答えの入力欄が日本語を入力できるようになれば、同じsidecarへかな・漢字表記の行を追加するだけで受け付けられる。
- イベントの発生日や対象プレイヤーが変わっても原文本文が同じなら同じ訳を利用する。原文本文が変わった場合は安全側で原文表示になる。
